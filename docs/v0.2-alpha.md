## Architecture Overview

NOZH is an adaptive performance optimization system for Minecraft 1.20.1, consisting of four architectural layers:

### Layer 1: Brain (PROMPT 1 - Contracts 1-6)

**Purpose:** Core decision-making and execution  
**Components:**

- **StateStore:** Immutable runtime state with invariant validation
- **ActionBus:** Single-threaded command orchestration (1 cmd/tick)
- **CapabilityProvider System:** Isolated providers with health tracking
- **Confidence Scoring:** Decay-based success tracking with environment detection
- **Governor Modes:** OFF/MANUAL_ASSIST/AUTO_CONSERVATIVE/AUTO_AGGRESSIVE
- **SimulationGovernor:** NO CASCADE rule enforcement (45s observation window)

**Guarantees:**

- Zero MC imports in `/core/**`
- Provider isolation (broken provider ≠ crash)
- Atomic apply with STRONG rollback
- Deterministic command processing

### Layer 2: Nervous System (PROMPT 3 - Contract 4)

**Purpose:** Performance metric collection without degradation  
**Components:**

- **TelemetryBuffer:** Ring buffer (512 cap), droppable, never blocks
- **TelemetrySnapshot:** Aggregated metrics (avg, p95, spikes)
- **NoiseDetector:** CV-based validity classification

**Guarantees:**

- Zero allocations per `add()`
- Thread-safe snapshot generation
- O(1) add operation

### Layer 3: Immune System (PROMPT 3 - Contracts 9-10 + Hardening)

**Purpose:** Self-defense and constraint enforcement  
**Components:**

- **Issue Detection:** Structured diagnostics (not log spam)
- **Paranoia Levels:** OFF/NORMAL/STRICT escalation
- **Hardware Presets:** 6 tiers (CAFETERA→NASA) with explicit constraints
- **StartupSelfcheck:** Critical component validation
- **CompatDetector:** Sodium/Iris/DH detection

**Guarantees:**

- Issues are aggregatable (no spam)
- Presets are limits, not scripts
- Governor respects preset bounds

### Layer 4: Senses & Voice (PROMPT 2)

**Purpose:** Visibility, explanation, and user control  
**Components:**

- **HUD:** 7 sections (Dashboard, Tuning, Providers, History, Benchmark, Issues, Chaos)
- **Explainability:** DecisionReport with full reasoning
- **Benchmark:** Noise-controlled measurement with validity classification
- **Chaos Runner:** 8 headless stress test scenarios

**Guarantees:**

- HUD never executes logic (only reads snapshots)
- Section-isolated rendering (try/catch per section)
- Performance budget: closed=0, open<0.5ms

## Benchmark Methodology

### Phases

1. **Warmup** (10s default): Stabilize system, discard samples
2. **Measure** (30s default): Collect samples via TelemetryBuffer
3. **Cooldown** (5s default): Governor disabled to prevent interference

### Validity Classification

- **VALID:** CV < 15% (low variance, reliable)
- **NOISY:** CV > 30% (high variance, unreliable)
- **INCONCLUSIVE:** Insufficient samples or medium variance

### Noise Detection

**Method:** Coefficient of Variation (CV)  
**Formula:** CV = (P95 - Avg) / Avg  
**Thresholds:** Configurable (defaults: 15%/30%)

### Export Format

**Location:** `config/nozh/nozh-benchmark.json`  
**Contains:** avg, p95, p99, spikes, sampleCount, validity, noiseMetric, notes

## Explainability

### DecisionReport Structure

- **Timestamp:** When decision was made
- **Context:** mode, tier, paranoia, cooldowns
- **Candidates:** Top 10 considered (capabilityId, confidence, tier, rejectedReason)
- **Selected:** Chosen action (or null if no action)
- **Reason:** i18n key explaining decision

### Reading Decisions

1. Check `reasonKey` for high-level explanation
2. Review `candidatesConsidered` to see what was evaluated
3. Check `rejectedReason` for each candidate to understand filtering
4. If `selected` is null, check cooldowns or paranoia level

## Chaos Tests

### 8 Scenarios

1. **Provider Init Failure:** Provider throws during initialization
2. **Invariant Violation:** Attempt to violate StateStore invariant
3. **Queue Overflow:** Fill ActionBus beyond capacity
4. **Telemetry Starvation:** Overflow TelemetryBuffer
5. **Governor Flapping:** Rapid state changes
6. **Preset Violation:** Action outside preset bounds
7. **SafeMode Dispatch:** Command while in SafeMode
8. **HUD Snapshot Corruption:** Invalid/null snapshot data

### Execution

**Command:** `/nozh chaos test`  
**Mode:** Headless (no UI required)  
**Result:** PASS/FAIL per scenario + aggregate report

## Troubleshooting

### SafeMode Activation

**Symptom:** System reports SafeMode active  
**Cause:** Repeated crashes or critical issue detected  
**Solution:**

1. Check `/nozh selfcheck` for critical issues
2. Review `config/nozh/nozh-state.json` for crash count
3. Use `/nozh safemode reset` after resolving root cause

### Provider Degraded/Broken

**Symptom:** Provider shows DEGRADED or BROKEN status  
**Cause:** Capability failed to apply or rollback failed  
**Solution:**

1. Check provider status reason in HUD→Providers
2. Review execution history for failures
3. Consider preset change if provider is tier-restricted

### Benchmark NOISY

**Symptom:** Benchmark classifies as NOISY (CV > 30%)  
**Cause:** High performance variance during measurement  
**Solution:**

1. Close background applications
2. Wait for system to stabilize
3. Run benchmark again
4. Consider STRICT config (longer measure phase)

### Telemetry Starvation

**Symptom:** High droppedSamples count, WARNING/CRITICAL issue  
**Cause:** TelemetryBuffer overflow (too many samples)  
**Solution:**

1. Verify minimum requirement: 1 sample = 1 frame
2. Check for extreme FPS (>500) causing overflow
3. Review benchmark configuration
